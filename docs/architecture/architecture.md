## Engine Knowledge Gap Summary

Локального справочника libGDX 1.14.2 нет. Конкретные API представления и интеграцию потоков необходимо сверять с документацией версии перед реализацией. Домен не использует API libGDX. Это не означает, что конкретные API непригодны или известны как несовместимые.

## System Layer Map

```text
desktop → presentation → application → domain
```

- **desktop:** запуск и платформа.
- **presentation:** libGDX, экраны и ввод.
- **application:** сценарии, таймер, пауза и решения ботов.
- **domain:** карты и планшеты, раунды, рынок, ресурсы, проект, эффекты и события.

Домен — пакет под `core/src/main/java/com/myjavacardgame/domain/`. Существующий Gradle-модуль `:core` зависит от libGDX: это **изоляция пакета**, а не модуля. При реализации нужна автоматическая проверка зависимости домена только от JDK и собственных доменных типов, включая запрет обратных зависимостей на внешние слои. Механизм и проверку транзитивной изоляции ещё предстоит определить.

## Module Ownership

- `GameSession` координирует доменные операции; внутренние области владеют своим состоянием.
- `cards/board`: экземпляры, роли, позиции, улучшения и активации.
- `round`: фазовое состояние, порядок игроков, номер раунда и результат.
- `market`: рынок, колода, сброс и правила сделок.
- `resources`: балансы, доход, расходы, вклад и депозит.
- `project`: требования и прогресс этапов.
- `effects`: активные, немедленные и отложенные эффекты.
- `events`: контракты доменных событий и наблюдателя.
- `application`: команды пользователя и бота, таймер, управление партией.
- `presentation` и `desktop`: представление и запуск; не владеют игровыми правилами.

## Data Flow

1. Ввод → application → синхронная команда домену → результат и неизменяемый снимок → UI.
2. После успешной операции доменные события доставляются через application подписчикам в порядке возникновения. Ошибка наблюдателя не отменяет операцию и не препятствует остальным подписчикам.
3. Таймер и пауза управляются в application; истечение создаёт команду домену. Боты подают те же команды и проходят те же проверки.
4. Данные карт, проекта и правил загружаются снаружи; источник случайности инъецируется. Игровые команды первоначально обрабатываются последовательно.
5. Сохранение и восстановление партии отложены; формат не выбран. Домен не выполняет файловый ввод-вывод.

## API Boundaries

- `GameSession.execute(GameCommand)` возвращает результат и события; отклонённая команда не изменяет состояние.
- `GameSession.snapshot()` возвращает неизменяемое представление без ссылок на изменяемые внутренние коллекции.
- `PhaseState` определяет допустимые команды и переходы фаз; правила эффектов остаются в своих доменных областях.
- `DomainEvent` и `GameObserver` — Java-контракты; подписка управляется через application.
- Случайность и время подменяемы для тестов; домен не читает системные часы.
- Конкретные классы, обработка ошибок и контракт подписки уточняются до реализации.

## Required ADRs

Обязательных ADR на текущем уровне процесса нет. При необходимости дальнейшей фиксации: граница домена; команды/фазы/события; порядок разрешения эффектов.

## Architecture Principles

1. Зависимости направлены к домену; libGDX не проникает в него.
2. Правила и игровые значения определяются согласованным дизайном и внешними данными.
3. Команды человека и ботов проходят одинаковые проверки.
4. Наблюдатели не владеют состоянием и не меняют результат уже выполненной операции.
5. Случайность и время контролируемы в тестах.
