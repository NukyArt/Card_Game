## Об игре

**Card_Game** — пошаговая карточная ПК-игра на Java 17 и libGDX. Развивайте своё игровое поле, приобретайте карты, выстраивайте производство и вкладывайте ресурсы в общий проект.

В текущем сценарии **«Фэнтезийный город»** игрок вместе с тремя ботами проходит пять этапов строительства: от лагеря строителей до открытия города. Задача — завершить проект до исчерпания лимита раундов.

Проект строится на принципах **Clean Architecture**: игровые правила отделены от графического интерфейса и платформенного запуска.

## Основные механики

### 🃏 Карты и производственные циклы

- Покупка карт на общем рынке.
- Размещение карт в роли базы или улучшения, если выбранная роль доступна.
- Активация баз с учётом установленных улучшений.
- Производственные эффекты с фиксированными выплатами, выбором ресурсов и случайными результатами.
- Внесение карт с игрового поля в строительство на этапах, где это необходимо.

### 💰 Экономика

- Четыре вида ресурсов: **золото, провиант, стройматериалы и свитки**.
- Регулярный доход, покупка и продажа карт, платное обновление рынка.
- Распределение ресурсов между развитием собственного поля и общим проектом.
- Депозит золота с начислением бонуса.
- Параметры экономики, каталоги карт и требования этапов вынесены в JSON.

### 🔄 Фазовая модель

Раунд состоит из четырёх последовательных фаз:

**Доход → Рынок → Производство → Депозит → Новый раунд**

Переходами управляет машина состояний. Игровая сессия проверяет допустимость команд, очерёдность участников и условия завершения партии.

### 🤖 ИИ участников

- Одиночная партия с тремя ботами.
- Выбор покупок с учётом недостающих ресурсов текущего этапа.
- Автоматическая активация производства и внесение вкладов в проект.
- Боты действуют через те же игровые команды и проверки, что и человек.

### 🏰 Поэтапное строительство

- Пять последовательных этапов с собственными требованиями.
- Эффекты завершения: выплаты участникам и изменения производства.
- Просмотр требований и прогресса строительства.
- Уведомления о завершении этапов и итоговый экран партии.

## Архитектура

В проекте два Gradle-модуля: **`core`** и **`desktop`**. Доменная модель находится внутри `core`, но не зависит от libGDX.

```text
desktop / LWJGL3
└── DesktopLauncher             Создание окна и запуск приложения
    │
    ▼
core
├── presentation/               Экраны, ввод, анимации и модели представления
├── application/                Сценарии приложения, загрузка данных и боты
└── domain/                     Независимые игровые правила
    ├── cards/                  Карты, роли и эффекты производства
    ├── board/                  Игровое поле
    ├── market/                 Рынок и торговля
    ├── resources/              Ресурсы
    ├── project/                Этапы общего строительства
    └── round/                  Сессия, команды и фазы партии
```

**Направление зависимостей:** интерфейс и прикладной слой используют доменную модель, а не наоборот.

Такое разделение позволяет проверять правила игры без создания окна и менять представление, не перенося игровую логику в код экранов.

## Сборка и запуск

### Требования

- **JDK 17**, доступный через `JAVA_HOME` или `PATH`.
- Интернет для первой загрузки Gradle и зависимостей.
- Графическое окружение для запуска игры.

Отдельная установка Gradle не нужна — в репозитории есть Gradle Wrapper.

Все команды выполняются из корня проекта.

### Запуск игры

**Linux / macOS / Git Bash:**

```bash
./gradlew desktop:run
```

**Windows PowerShell / CMD:**

```powershell
.\gradlew.bat desktop:run
```

> Модуль запуска называется `desktop`. LWJGL3 подключён внутри него как бэкенд libGDX, а не как отдельный Gradle-модуль.

### Полная сборка

```bash
./gradlew build
```

### Подготовка дистрибутива

```bash
./gradlew desktop:installDist
```

Дистрибутив со скриптами запуска и зависимостями появится в `desktop/build/install/`. Для его запуска требуется установленная Java 17.

## Тестирование

Запуск всех автоматических тестов:

```bash
./gradlew test
```

Запуск тестов игрового модуля:

```bash
./gradlew core:test
```

Тесты покрывают:

- переходы между фазами и обработку игровых команд;
- активацию карт и производственные эффекты;
- экономику рынка и вклады в строительство;
- требования этапов и применение их эффектов;
- загрузку каталогов и настроек;
- поведение игрового драйвера, навигацию и модели представления.

HTML-отчёт тестов доступен после выполнения:

```text
core/build/reports/tests/test/index.html
```

Автоматические проверки дополняются ручным тестированием интерфейса и обычных игровых партий.

## Статус разработки

Игра находится в активной разработке. Реализованы текущий сценарий, партия с ботами, рынок, производство и поэтапное строительство. Баланс и удобство интерфейса продолжают дорабатываться.

Выбор дополнительных уровней сложности пока недоступен.
